# Todo 039: Payment Status + Due Date on Backfill Invoice Creation

**Status:** ✅ Done

## Description
Follow-up to Todo 038: creating a backfilled invoice from Delivery Reconciliation with no payment
info always left it fully outstanding, which correctly (but unhelpfully) tripped ERPNext's own
credit-limit check on every backfill. Adds a Payment Status choice (Paid / Partial / Unpaid) to the
Create Invoice modal, an Amount Collected field for Partial, and a Due Date field whenever the
status isn't Paid.

## Files Changed
- `klik_pos/api/sales_invoice.py` (`queue_sales_invoice` - opt-in `pay_in_full` flag)
- `klik_pos/api/delivery.py` (`create_invoice_from_delivery_report` - `payment_status` /
  `amount_collected` / `due_date` params)
- `klik_spa/src/services/delivery.ts` (`createInvoiceFromDeliveryReport` signature)
- `klik_spa/src/components/delivery/CreateInvoiceFromReportModal.tsx` (payment status UI)
