# Todo 051: Link/Unlink Unreferenced Invoices + Confirm Dialogs

**Status:** ✅ Done

## Description
Follow-up to Todo 050: closes the loop between the "Invoices without a physical reference" list
and the numbered checklist's "Unresolved" pages. Also retrofits confirmation dialogs onto every
manual action in Daily Reconciliation (Confirm Self-Pickup, Confirm Delivered, Mark/Unmark Void,
Unlink), per the user's explicit request.

  `unlink_invoice_page(invoice_name)`

- `klik_spa/src/pages/DailyReconciliationPage.tsx` - `LinkPagePicker` (new),

## Implementation notes (2026-08-02)

### Real bug found: `custom_invoice_ref` blocks post-submit edits entirely
First live test of `link_invoice_to_page` failed: `Not allowed to change Invoice Ref after
submission from 0 to 703`. The Custom Field has `allow_on_submit: 0` (a pre-existing gap - see
`bugs.md` BUG-002, this field was created directly on the site and never fully configured), which
blocks any `doc.save()`-based edit post-submission, not just this feature. Rather than flipping
`allow_on_submit` globally (which would also open the field to direct desk-form editing on any
submitted invoice - a bigger, more consequential change than this endpoint needs), both
`link_invoice_to_page` and `unlink_invoice_page` use `frappe.db.set_value` to touch just that one
column, bypassing the document-level submit check in a deliberately narrow way.

### Design choices (decided with the user, 2026-08-02)
- Confirm Self-Pickup/Confirm Delivered on unreferenced invoices only show when the invoice's
  `custom_delivery_status` is still Pending/Not Delivered - matches the numbered checklist's
  existing Pending Fulfillment gating.
- Link entry point is one-directional: only from the unreferenced-invoice row ("Link to Page"),
  not also from the Unresolved row - one clear way to do it.
- Unlink is scoped to Pending Fulfillment rows only, not any resolved invoice - unlinking a page
  reference from an invoice whose delivery/pickup is already confirmed is a materially riskier
  action than undoing an unconfirmed data-entry attachment, so it's deliberately not offered there
  (no way to distinguish "linked via this feature" from "entered normally at checkout" without new
  tracking state, so the safe middle ground is gating by delivery-status instead).
- Link targets only Unresolved pages, never Reported-No-Invoice (which already has its own
  Delivery-Report-based Create Invoice flow this would conflict with).
- `LinkPagePicker`'s dropdown-plus-explicit-"Link to Page N"-button doubles as its own
  confirmation step, rather than a separate picker followed by a second `ConfirmDialog` - avoids a
  redundant double-confirm for what's already a deliberate two-field choice.

### Live verification (bench console against hd.phirun.me)
Full round trip: link an unreferenced invoice onto a genuinely Unresolved page (succeeds, page
becomes Pending Fulfillment, invoice drops out of the unreferenced list), reject linking onto a
non-Unresolved page, reject linking an invoice that already has a reference, unlink while still
Pending (succeeds, reverses both effects). All test data cleaned up after.
