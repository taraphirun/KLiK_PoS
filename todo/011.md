# Todo 011: Frontend Payment Dialog Credit Limit Validation

**Status:** ✅ Done

## Description
Integrate the pre-submit credit limit check (Todo 010, which wraps ERPNext core's existing
`get_credit_limit`/`get_customer_outstanding` — no new balance math) into the frontend checkout
flow, warning/blocking submission before the draft invoice is created if the limit would be
exceeded. Core's `on_submit` check remains the actual enforcement point; this is purely proactive
UX so the cashier doesn't fill out the whole Payment Dialog only to have submission fail.

## Estimated Time
45-60 minutes

## Files to Change
- `klik_spa/src/services/salesInvoice.ts`
- `klik_spa/src/components/dialog/PaymentDialog.tsx`

## Dependencies
- Todo 010

## Acceptance Criteria
- Validation occurs before order submission.
- A prominent red alert banner displays the exceeded amount if validation fails.
- The submit button is disabled when the credit limit is exceeded.

## Risks
- Network latency during validation might cause a noticeable delay in the checkout experience.
