# Todo 017: Frontend Search Bar and Order Summary Refinements

**Status:** 🔷 In progress (partial — see split below)

## Description
Refine the search bar to properly accept keyboard events and update the order summary to include a
custom invoice reference input.

## Split (2026-07-30)
- ✅ **Done**: `custom_invoice_ref` input added to `OrderSummary.tsx` ("Invoice Reference
  (optional)", above the cart list). Threaded through as a new `customInvoiceRef` prop on
  `PaymentDialog` (not originally in the "files to change" list, but that's where the actual submit
  payload — `buildPaymentData`/hold-order `orderData` — is assembled, matching how the existing
  `taxPin` field already works) and included in both the real-submit and hold-order payloads as
  `customInvoiceRef`/`custom_invoice_ref` (backend's `parse_invoice_data` already reads either key).
  Reset alongside `itemDiscounts` in `handleClearCart`.
- ⬜ **Deferred with Todo 016's grid-nav half**: `SearchBar` forwarding raw `onKeyDown` events.
  `SearchBar` was converted to `forwardRef` so `Cmd/Ctrl+F` can imperatively focus it (Todo 016),
  but that's a different capability from forwarding `onKeyDown` — which only has a purpose once
  arrow-key grid navigation exists to consume it. Adding an unused `onKeyDown` prop now would be
  dead plumbing.

## Files Changed
- `klik_spa/src/components/order/OrderSummary.tsx`: `customInvoiceRef` state + input, reset on
  clear, passed to `PaymentDialog`.
- `klik_spa/src/components/dialog/PaymentDialog.tsx` / `types.ts`: accept `customInvoiceRef` prop,
  include in submit and hold-order payloads.
- `klik_spa/src/components/SearchBar.tsx`: `forwardRef` (see Todo 016) — not `onKeyDown` forwarding.

## Dependencies
- Todo 016 (for the deferred `onKeyDown` half only)
