# Todo 016: Frontend Global Keyboard Navigation

**Status:** 🔷 In progress (partial — see split below)

## Description
Implement global keyboard shortcuts to enhance navigation efficiency for POS operators.

## Split (2026-07-30)
User couldn't test live UI this session, and two of the four shortcuts required inventing new
functionality rather than wiring existing pieces (no highlighted/selected-item state exists
anywhere in `ProductGrid.tsx`, and **no quantity dialog component exists in the codebase at all** —
clicking a product adds it straight to cart at qty 1, adjusted later). Building both blind, without
being able to test the interaction live, was judged too risky. Split by user choice ("do the safe
parts only"):

- ✅ **Done**: `Cmd/Ctrl+F` focuses the search bar; `Escape` clears the search bar (scoped to when
  the search input itself has focus, to avoid interfering with other components' own Escape
  handling, e.g. `CustomerSearchSection`/`AutoComplete` dropdowns which already handle their own
  Escape).
- ⬜ **Deferred until live testing is possible**: `ArrowUp/ArrowDown` product-grid navigation and
  `Shift+Enter` to open a quantity dialog. Needs: new highlighted-item state in `ProductGrid.tsx`,
  and a new quantity-input modal (doesn't exist yet) before Shift+Enter has anything to open.

## Estimated Time
Done portion: ~20 minutes. Deferred portion: revisit estimate once live-testable (original
estimate assumed both existed to wire up; they don't — expect more like 90-120 minutes for the
grid nav + new quantity dialog).

## Files Changed
- `klik_spa/src/components/RetailPOSLayout.tsx`: added a `searchInputRef` and a `window` keydown
  listener (desktop only) for Cmd/Ctrl+F and the scoped Escape-clear.
- `klik_spa/src/components/SearchBar.tsx`: converted to `forwardRef` so the underlying `<input>`
  can be focused imperatively.
- `klik_spa/src/components/MenuGrid.tsx`: threads `searchInputRef` through to `SearchBar`.

## Dependencies
- None for the done portion. The deferred portion has no blocking dependency either, just needs a
  live-testing session.

## Acceptance Criteria
- [x] `Cmd/Ctrl + F` focuses the search bar.
- [x] `Escape` clears the search bar (when it has focus).
- [ ] `ArrowUp / ArrowDown` navigates the search results grid. (deferred)
- [ ] `Shift+Enter` opens the quantity dialog for the highlighted product. (deferred — dialog
      doesn't exist yet)

## Risks
- Keybinding conflicts with browser default shortcuts or other existing app shortcuts — checked:
  no other component intercepts Cmd/Ctrl+F, and Escape is scoped to search-input focus so it
  doesn't fight with `CustomerSearchSection`/`AutoComplete`'s own Escape handling.
