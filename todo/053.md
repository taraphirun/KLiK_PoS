# Todo 053: Full-Range Booklet Readiness Check + Close-Booklet Gate

**Status:** ✅ Done

## Description
The user clarified that "Check Gaps" was meant to answer a different question than what it
actually did: not "did the driver skip logging a page" (the old Delivery-Report-only, interior-
span-only implementation) but "is every page in this booklet's full range resolved, so it can be
closed" - and `close_booklet` had **zero validation** enforcing that despite its own docstring
claiming otherwise.

## Files Changed
- `klik_pos/api/booklet.py` - `_classify_booklet_range` (new, reuses `_classify_number` from the
  daily checklist), `get_booklet_status` (replaces `get_booklet_gaps`), `close_booklet` now
  hard-blocked
- `klik_spa/src/services/booklet.ts` - `getBookletStatus` replaces `getBookletGaps`
- `klik_spa/src/pages/BookletsPage.tsx` - "Check Gaps"/"Hide Gaps" renamed "Check Status"/"Hide
  Status", full per-number status table (same visual language as Daily Reconciliation) replaces
  the old "Missing pages: x, y" list

## Implementation notes (2026-08-02)

### Same classification, different scope
`_classify_booklet_range` reuses the exact `_classify_number` helper `_classify_daily_checklist`
already uses - the only difference is what numbers get iterated and where the invoice/report data
comes from: the *entire* `start_number`-`end_number` range (not just touched numbers), gathered
booklet-wide across all time (`Sales Invoice.custom_invoice_ref` between the range, `Delivery
Report.booklet = this booklet`) rather than scoped to one date. This is deliberately different
from `_classify_daily_checklist`'s interior-only philosophy - a check gating *permanent closure*
of a booklet can't stop at "what's been touched so far."

### close_booklet gate mirrors close_daily_reconciliation exactly
Same pattern: recompute fresh (never trust a stale frontend view), collect every number not in
`CLOSABLE_STATUSES` (reused from the daily-checklist module-level constant), throw listing exactly
which pages are still blocking if any exist.

### Live verification (bench console against hd.phirun.me)
Small 6-page test booklet: confirmed `get_booklet_status` returns "Unresolved" for every page with
nothing done yet, `close_booklet` blocks with a clear "6 page(s) still need action" message,
resolving all 6 (mix of void/self-pickup/delivered) makes `close_booklet` succeed. Test data
cleaned up fully (no leftover cancelled invoices this time).
