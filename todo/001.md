# Todo 001: Backend `is_pos` Determination and Shift Tagging

**Status:** ✅ Done

## Description
Implement the logic in the sales invoice API to determine if an invoice is a POS transaction based on the amount paid, and ensure all invoices are tagged with the current POS opening entry.

## Estimated Time
30-60 minutes

## Files to Change
- `klik_pos/api/sales_invoice.py`

## Dependencies
- None

## Acceptance Criteria
- If `amount_paid > 0`, `is_pos` is set to 1 and `pos_profile` is populated.
- If `amount_paid == 0`, `is_pos` is set to 0 and `pos_profile` is None.
- `custom_pos_opening_entry` is populated for all invoices generated during a shift.

## Risks
- Affecting standard non-POS invoice creation if the logic leaks outside the POS API context.
