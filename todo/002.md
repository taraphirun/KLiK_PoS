# Todo 002: Backend Partial Payment and Customer Type Handling

## Description
Implement safeguards for partial payments, normalize customer type checks, and map the custom invoice reference field.

## Estimated Time
30-60 minutes

## Files to Change
- `klik_pos/api/sales_invoice.py`

## Dependencies
- Todo 001

## Acceptance Criteria
- Partial payments correctly set `allow_partial_payment = 1` or explicitly record `paid_amount` and `outstanding_amount`.
- Customer type checks are case-insensitive.
- `custom_invoice_ref` from the payload is successfully mapped to the Sales Invoice document.

## Risks
- Incorrectly calculated outstanding amounts could lead to accounting discrepancies.
