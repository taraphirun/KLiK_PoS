# Todo 050: Unreferenced Invoices in Daily Reconciliation

**Status:** ✅ Done

## Description
Follow-up to Module 17 ([phase-16.md](../phases/phase-16.md)): a Sales Invoice created with no
`custom_invoice_ref` at all (a digital-only sale, or a cashier who forgot to type the paper
number) was completely invisible to the Daily Reconciliation checklist - the classification only
ever looks at referenced numbers. Adds visibility for these, deliberately **not** as part of the
blocking checklist: the user was explicit that Close Day should stay scoped purely to the physical
booklet's min-max range - this is informational only, to catch a forgotten paper-number entry vs.
a genuinely paperless sale.

## Files Changed
- `klik_pos/api/booklet.py` - `_get_unreferenced_invoices(date)` (new), wired into
  `get_daily_reconciliation`'s response as `unreferenced_invoices`
- `klik_spa/src/services/booklet.ts` - `UnreferencedInvoice` type, `DailyReconciliation.unreferenced_invoices`
- `klik_spa/src/pages/DailyReconciliationPage.tsx` - new read-only section below the numbered
  checklist, rendered only when the list is non-empty, explicitly labeled "informational only,
  doesn't block closing"

## Implementation notes (2026-08-02)
Query: `Sales Invoice` where `docstatus=1`, `posting_date=date`, `custom_invoice_ref in (0, None)`
- both `0` (the field's untouched Int default, see BUG-002 in `bugs.md`) and `NULL` are treated as
  "no reference," matching how the rest of this module already has to handle that field's quirky
  default. Computed unconditionally alongside `_classify_daily_checklist`, independent of whether
  the numbered range has any activity that day - a day can have zero booklet-tracked invoices and
  still show unreferenced ones, or vice versa.

Live-verified via `bench console` against `hd.phirun.me`: created an invoice with no
`custom_invoice_ref` dated a test date, confirmed it appeared in `unreferenced_invoices` while the
numbered `data` list stayed empty for that date. Cleaned up after.
