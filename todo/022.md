# Todo 022: Auto-Match Logic with Confidence Scoring

**Status:** ⬜ Not started

## Description
Given a Delivery Report's fields — **already extracted and OCR-resolved by the bot** (invoice
number, amount, customer, driver, delivery status; see phase-09 "System boundary") — find the
most likely Sales Invoice and assign a confidence score. This is **structured-to-structured**
matching only: KlikPOS performs **no OCR/AI** (the bot did that). It is a **suggestion engine** —
it never mutates the invoice. It sets `matched_invoice`, `match_confidence`, and moves
`reconciliation_status` from `Unmatched` to `Suggested` when a candidate is found.

## Estimated Time
2-3 hours

## Files to Change
- `klik_pos/api/delivery.py` (MODIFY — add `match_delivery_report(report)` and helpers)

## Matching Strategy (highest confidence first)
1. **Exact invoice number**: `reported_invoice_no` == Sales Invoice `name` (or `custom_invoice_ref`).
   → confidence ~1.0.
2. **Fuzzy invoice number**: normalized/trimmed/typo-tolerant match on invoice no.
   → high confidence, needs review.
3. **Attribute match** when invoice no is missing/wrong: score candidates by
   customer + outstanding amount ≈ `amount_collected` + posting date near `delivery_timestamp`
   + driver == `custom_delivery_personnel`.
   → confidence from weighted field agreement.
- Prefer invoices that are **Unpaid / Partly Paid** and not yet delivered when scoring ties.

## Acceptance Criteria
- Exact invoice-number matches score at/near 1.0 and set status `Suggested`.
- When no candidate crosses a minimum threshold, `matched_invoice` stays empty and status
  remains `Unmatched`.
- The function is pure/read-only with respect to Sales Invoices — it writes only to the
  Delivery Report record.
- Confidence is deterministic and explainable (store which signals matched, e.g. in a notes or
  JSON field), so the reconciliation UI can show *why* it matched.

## Dependencies

## Risks
- Fuzzy matching false positives are the main danger — bias toward leaving as `Unmatched` when
  uncertain rather than suggesting a wrong invoice.
- Amount matching must use `outstanding_amount` (not `grand_total`) for partial/credit invoices
  from Phase 1, or collected-cash amounts won't line up.
