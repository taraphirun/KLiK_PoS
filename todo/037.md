# Todo 037: Customer List Credit Visibility

**Status:** ⬜ Not started

## Description
Show each customer's current credit used (outstanding balance) and total allowed credit (credit
limit) on the Customers list page (`/customers`), reusing the same core credit-limit sources as
Phase 4 (Todo 010) so the displayed numbers always agree with what would block a sale.

## Estimated Time
30-45 minutes

## Files to Change
- `klik_pos/api/customer.py`
- `klik_spa/src/hooks/useCustomers.ts`
- `klik_spa/src/types/customer.ts`
- `klik_spa/src/components/CustomersPage.tsx`

## Implementation Notes
- Backend (`get_customers`): batch-attach `credit_limit` and `credit_used` to each row for the
  current page only (this is a list endpoint, so avoid one `get_customer_outstanding()` call per
  customer):
  - `credit_limit`: reuse `erpnext...customer.get_credit_limit(customer, company)` per customer (cheap
    single-value lookups), or batch via one query against `Customer Credit Limit` + the Company
    default, following the same pattern as the existing `_get_customer_telegram_links` batch helper.
  - `credit_used`: one grouped GL Entry query (`party_type='Customer' AND is_cancelled=0 AND
    company=%s AND party IN (...)`) across the current page's customer names, mirroring the
    GL-Entry-based computation in `get_customer_outstanding` (skip the Sales-Order-based add-on —
    not relevant for POS-originated invoices).
- Frontend: add `creditLimit`/`creditUsed` to the `Customer` type and map `credit_limit`/`credit_used`
  onto them in `useCustomers.ts`; add a "Credit" column to both the desktop and mobile tables in
  `CustomersPage.tsx` (e.g. "Used: X / Limit: Y", or "No Limit" when `credit_limit` is 0).

## Dependencies
- None (independent of Todo 010/011, but reuses the same core functions for consistency)

## Acceptance Criteria
- Customers list shows credit used and credit limit per customer without a per-row core outstanding
  query (batched).
- Customers with no configured credit limit show "No Limit" rather than 0/0.
- Numbers match what `check_credit_limit`/Todo 010 would compute for the same customer.

## Risks
- GL Entry query performance on large ledgers — batching per page (not per customer, not for the
  whole customer table) keeps this bounded to the page size (default 100, capped at 500).
