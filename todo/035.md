# Todo 035: Media Buffering + Upload to Frappe File

**Status:** ⬜ Not started

## Description
Buffer delivery photos and voice notes locally at capture time and upload them to Frappe File on
sync, replacing MinIO. Attach the uploaded files to the corresponding Delivery Report.

## Estimated Time
2-3 hours

## Files to Change
- Bot side (`hd-delivery-telegram/delivery-bot`): download Telegram media to local disk at capture;
  upload during sync.
- KlikPOS side (`klik_pos/api/delivery.py`): accept file uploads and attach to a Delivery Report
  (or reuse Frappe's standard file-upload + `attach` linkage).

## Behaviour
- At capture: fetch the Telegram file(s) to a local media dir; store paths in the SQLite row
  (Todo 033).
- At sync: upload each file to Frappe (Frappe File, private), link it to the Delivery Report's
  `photos` / `voice_note` fields, then it may be pruned locally after successful attach.
- Order: upload media first, then submit/patch the Delivery Report so links resolve.

## Acceptance Criteria
- Photos/voice captured offline are stored locally and survive a restart.
- On sync, media lands in Frappe File, attached to the right Delivery Report, viewable from the
  deliveries UI (Todo 029).
- Re-sync does not create duplicate file attachments (idempotent per `bot_delivery_id` + file).

## Dependencies
- Todo 033, 034; Phase 9 Todo 019 (photo/voice fields), Todo 029 (viewing media)

## Risks
- Large media over poor connectivity — compress/limit resolution; upload with resumable/retry.
- Private vs public files — delivery photos should be private Frappe files with proper permissions.
- Local disk growth — prune only after confirmed successful attach.
