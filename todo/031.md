# Todo 031: Realtime Delivery Events

**Status:** ⬜ Not started

## Description
Emit Frappe realtime events when a Delivery Report is created or its reconciliation state changes,
so the live map (and any open list) updates without polling.

## Estimated Time
1-2 hours

## Files to Change
- `klik_pos/klik_pos/doctype/delivery_report/delivery_report.py` (MODIFY — `on_update` / `after_insert`)
- `klik_pos/api/delivery.py` (MODIFY — emit on reconcile actions if not covered by doc events)

## Requirements
- On new Delivery Report (ingested via Todo 021) publish an event with the minimal map payload:
  id, lat/long, driver, completion + payment status, recon status.
- On reconcile (confirm/reject/re-match) publish an update event.
- Use a stable event name (e.g. `delivery_report_update`) and scope to the right user/role room.

## Acceptance Criteria
- Creating/reconciling a Delivery Report pushes an event the SPA can subscribe to.
- Payload is minimal (no photos/raw payload) to keep the socket light.
- No event on unrelated doctype saves.

## Dependencies
- Phase 9 (Todo 019, 021, 023)

## Risks
- Realtime room/permission scoping — don't broadcast delivery locations to unauthorized sessions.
- High delivery volume could be chatty; debounce or batch if needed.
