# Todo 042: Booklet Lifecycle Scheduler

**Status:** ✅ Done

## Description
Hourly status computation for every open (Active/Stalled/Ready for Review) booklet, porting
`booklet-lifecycle.service.ts`'s `checkBooklets` cron. Pure computation only - no Telegram
involved here, unlike the original (see [phase-15.md](../phases/phase-15.md)'s alert-direction
decision and Todo 043).

## Files Changed
- `klik_pos/api/booklet.py` (`check_booklet_lifecycle`)
- `klik_pos/hooks.py` (`scheduler_events["hourly"]`)

## Implementation notes (2026-08-02)
For each open booklet: gathers its linked Delivery Reports, and
- No reports yet + past the stall window since the booklet's own creation → Stalled.
- `len(reports) >= pages_per_booklet` OR the booklet's `end_number` has been reported → Ready for
  Review (checked before the stall path, matching the original's precedence).
- Otherwise: Stalled if the most recent report is older than the stall window (VIP booklets get a
  longer window - `vip_booklet_stall_days` vs `normal_booklet_stall_days`), else Active (including
  the auto-recovery case: a booklet that had stalled but has since received a new report goes back
  to Active, same as the original).

Live-verified via `bench console` against `hd.phirun.me`: backdated a booklet's `creation` past
the stall window with no reports (→ Stalled), matched a booklet's `end_number` (→ Ready for
Review), left a normal booklet with a recent report alone (→ stays Active). All test booklets/
reports deleted after.
