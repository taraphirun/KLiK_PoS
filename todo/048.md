## Implementation notes (2026-08-02)

### Reusing CreateInvoiceFromReportModal for "Reported, No Invoice" rows
Rather than building a third invoice-creation modal, "Reported, No Invoice" rows reuse the
existing `CreateInvoiceFromReportModal` with a minimal constructed `DeliveryReport` object (just
`name`/`reported_invoice_no` from the checklist row, cast `as DeliveryReport`) - the modal's other
field reads (`delivery_timestamp`, `payment_status`, `photos`) all degrade gracefully to sensible
defaults when absent. "Unresolved" rows (no report at all) get the new
`CreateInvoiceForPageModal` instead, since there's no report to construct even a minimal object
from.

### Reopen gating
The Reopen button is shown only when `userInfo.roles` includes `System Manager` - a UX nicety
only, the real enforcement is server-side (`reopen_daily_reconciliation`'s own role check). No
dedicated `is_system_manager` flag exists on `UserInfo` today, so this reads the raw `roles` array
directly rather than adding one for a single call site.

### Blocking-numbers extraction is string-parsed, deliberately narrow
`close_daily_reconciliation`'s error message ends with "...before <date> can be closed: 605, 608,
609" - the frontend splits on the final colon before regex-matching digits, specifically to avoid
picking up digits from the date or the leading count earlier in the sentence.
