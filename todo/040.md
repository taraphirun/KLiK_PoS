# Todo 040: Delivery Photo Viewer

**Status:** ✅ Done

## Description
There was no way to view a Delivery Report's attached photos anywhere in KlikPOS - a real gap once
Todo 038/039 let staff reference them while manually entering items for a backfilled invoice. Adds
a thumbnail strip (Delivery Reconciliation report cards + the top of the Create Invoice modal) that
opens a full-screen zoomable viewer.

## Files Changed
- `klik_pos/klik_spa/src/services/delivery.ts` (`photos` field type fix - see below;
  `parseDeliveryPhotos()` helper)
- `klik_spa/src/components/delivery/DeliveryPhotoStrip.tsx` (new)
- `klik_spa/src/pages/DeliveryReconciliationPage.tsx` (renders the strip on each report card)
- `klik_spa/src/components/delivery/CreateInvoiceFromReportModal.tsx` (renders the strip)

## Implementation notes (2026-08-01)

### A real bug found along the way
`DeliveryReport.photos` comes back from `get_delivery_reports` as a **raw JSON string** (e.g.
`'["/private/files/x.jpg"]'`) - `frappe.get_all()` doesn't auto-parse JSON fieldtype columns. The
frontend type declared `string[]`, which was simply wrong; nothing had ever rendered the field to
notice. Fixed by correcting the type to `string | null` and adding `parseDeliveryPhotos()` to
parse it safely everywhere it's read.

### Viewer iteration
Went through three versions in response to live feedback, each a real lesson:
1. **New-tab links** - simplest, worked, but poor UX (context switch away from the app).
2. **Hand-rolled inline lightbox** - wheel-based zoom anchored at the cursor, drag-to-pan, then
   added real touch handling (pinch via two-finger `touchmove` distance ratio, one-finger pan,
   double-tap). Hit - and fixed - a real React gotcha along the way: `onWheel`/`onTouch*` JSX props
   attach *passive* native listeners, so `event.preventDefault()` inside them silently does nothing
   (the page kept scrolling behind the "modal" despite the handler firing) - fixed by attaching
   real listeners via `addEventListener(..., { passive: false })` in a `useEffect` instead.
   Functionally complete but felt rough ("not so smooth") compared to a dedicated library.
3. **`yet-another-react-lightbox` + its Zoom plugin** (final) - replaced the hand-rolled version
   entirely. Checked npm directly rather than going from memory before recommending it: v3.32.2,
   published the day before this was built, React 19 compatible. Gets pinch/wheel/double-tap/pan
   with proper gesture smoothing for free; `scrollToZoom: true` covers the original "mouse or
   trackpad" ask, touch pinch is core behavior needing no extra config. The hand-rolled
   `DeliveryPhotoLightbox.tsx` was deleted outright once confirmed unused elsewhere.

### Access control gap (flagged, not fixed this pass)
While verifying, found `Delivery Report` read permission is granted only to `System Manager` and
the bot's own `Delivery Bot` service role (`Custom DocPerm`, not the doctype's fixture). Since
`get_delivery_reports` uses a permission-checked `frappe.get_all()` (no `ignore_permissions`), any
KlikPOS user without System Manager gets a silently empty Reconciliation page today - not something
this todo introduced, but it directly bounds who can use the photo viewer (or Create Invoice, or
reconciliation at all). Not resolved - flagged to the user, no role decision made yet.
