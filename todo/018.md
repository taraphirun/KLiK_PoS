# Todo 018: Create Custom Print Format JSON

**Status:** ✅ Done

## Description
Define the JSON structure for the custom POS invoice print format that includes required fields like payment breakdown and status indicators.

## History (2026-07-30)
Checked first, per the established pattern: a `DS POS Invoice KLiK` print format already existed in
the site's database (built directly in the Desk UI, module `KLiK PoS`), covering payment breakdown
and status indicators already. It just wasn't exported into the repo. Rescoped to: export it, then
add the two genuinely missing pieces (`custom_description`, customer credit info).

## Files Changed
- `klik_pos/klik_pos/print_format/ds_pos_invoice_klik/ds_pos_invoice_klik.json` (new, via
  `bench export-doc`): added `item.custom_description` under each line item, and a credit-info
  block (Credit Limit / Credit Used / Available) in the customer info section, shown only when
  `credit_info.credit_limit` is set.
- `klik_pos/klik_pos/utils.py`: new `get_customer_credit_summary(customer, company=None)`,
  wrapping `klik_pos.api.customer._get_customer_credit_info` for a single customer (lazy import to
  avoid a circular import — `api.customer` already imports from this module).
- `klik_pos/hooks.py`: filled in the previously-commented-out `jinja` hook scaffold to register
  `get_customer_credit_summary` as a print-format Jinja method.

## Dependencies
- None

## Acceptance Criteria
- [x] Print format JSON is properly structured and installable by Frappe (re-imported via
      `frappe.reload_doc` and confirmed the DB copy matches; `bench build` runs clean).
- [x] Includes `custom_description`, payment breakdown, credit info, and status indicators.
      Verified end-to-end via `bench console` / `frappe.get_print` against real invoices: a
      walk-in customer (credit section correctly hidden), a credit customer with `credit_limit=100`
      (renders correct Credit Limit/Used/Available figures), and an in-memory item with
      `custom_description` set (renders correctly; no error when blank).

## Known follow-up
Not wired as the default print format anywhere yet — `Phirun` POS Profile's `print_format` is
still empty. Flagged for the user rather than changed, since setting a live profile's print
default is an operational decision.

## Risks
- Syntax errors in the JSON could cause deployment or site initialization failures in Frappe —
  validated with `python3 -m json.tool` and a real `frappe.reload_doc` round-trip before commit.
